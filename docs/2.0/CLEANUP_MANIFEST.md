## 3. `packages/auth/dist` untracking — STOPPED (would break the live deploy)

**Claim under test:** "The deploy path uses project references / `tsc --build`." **That claim is FALSE.**

Evidence:
- `railway.json` → `build.buildCommand` = `echo 'Using pre-compiled dist' && ls apps/api/dist/modules/academy-command/` — **no compilation step.**
- `railway.json` → `deploy.startCommand` = `node apps/api/dist/index.js`.
- The committed `apps/api/dist/**` **`require('@packages/auth')`** at runtime (`dist/auth.js`, `dist/modules/*/*.service.js`), resolving through `apps/api/node_modules/@packages/auth` → `../../../../packages/auth` (package `main` = `dist/index.js`).
- `dist/` is in `.gitignore` (line 22), but the deployed artifacts are **committed**, and the deploy **never rebuilds** them. Railway ships the committed tree; untracked files are absent.
- Empirical proof of the dependency: with `packages/auth/dist` temporarily moved aside, `pnpm --filter @apps/api run typecheck` → **exit 2**, `TS2307: Cannot find module '@packages/auth'`. (Restored immediately; files intact.)
- The only path that rebuilds is the root `build` script (`pnpm build:v1` → `pnpm --filter @apps/api build` = `tsc --build`), which is **not** what Railway runs.

**Action taken: NONE.** Per the task's stop-condition ("if something depends on the COMMITTED dist rather than building it → STOP, revert staging, report"), `git rm -r --cached packages/auth/dist` was **NOT** executed. Nothing was staged, so nothing needed reverting.

**Owner decision required — two mutually exclusive fixes:**
1. **Leave `packages/auth/dist` tracked** (status quo) and accept staleness; **or**
2. **Switch Railway to a real build** (`buildCommand` = `pnpm --filter @apps/api build`) **and** update CI (`.github/workflows/ci.yml:40` builds only `@tuf/shared`, then runs `@apps/api typecheck`) to build all referenced packages **before** untracking `dist`.

Do **not** untrack `packages/auth/dist` (or `apps/api/dist`) without first fixing the deploy build command — the API will crash on boot.

> Note: `apps/api/dist/**`, `apps/web/dist/**`, and `packages/{database,env,logger}/dist/**` are **also** committed despite `.gitignore`. Same systemic issue; same owner decision. Out of the bounded scope to change.

### 4b. Hardcoded admin backdoor in the RUNTIME (CRITICAL — reported, NOT fixed)

`apps/api/src/index.ts:293-308` (compiled into the deployed `apps/api/dist/index.js:242-256`) resets on **every API boot**:

```
UPDATE users SET credential_hash = <scrypt('8188')>, must_change_credential = false,
  failed_credential_attempts = 0, locked_until = NULL
WHERE email = 'keith@tufsports.us'
   OR (role = 'ADMIN' AND id = (SELECT MIN(id) FROM users WHERE role = 'ADMIN'))
```

The PIN **`8188` is hardcoded** and re-applied at every startup, disabling forced-credential-change and clearing lockouts. This is a live backdoor reachable by anyone who knows `8188` and is far more dangerous than the untracked `reset_admin_pin.js` (which does the same thing once). Referenced in `docs/2.0/AUDIT_SUBSYSTEMS.md:136` as a known issue. **Out of the four-item scope — REPORT only.** Must be removed/gated before public connection.
